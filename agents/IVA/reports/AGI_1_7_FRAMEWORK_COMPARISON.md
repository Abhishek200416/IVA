## 1. Executive Summary

To remedy the 10 proven baseline defects of AGI 1.6 (`docs/AGI_1_7_BASELINE_AUDIT.md`) without destabilizing the host Windows environment or violating Directive 0 (sole model `gemini-3.8-flash-high` accessed via `agy.exe`), we conducted an engineering audit across nine leading external agent orchestration, durability, memory, and evaluation frameworks:

1. **AIOS** (`agiresearch/AIOS`)
2. **LangGraph** (`langchain-ai/langgraph`)
3. **AutoGen / Magentic-One** (`microsoft/autogen`)
4. **Temporal Python SDK** (`temporalio/sdk-python`)
5. **PydanticAI** (`pydantic/pydantic-ai`)
6. **OpenHands SDK** (`All-Hands-AI/OpenHands`)
7. **CrewAI** (`crewAIInc/crewAI`)
8. **Letta / Mem0** (`letta-ai/letta`, `mem0ai/mem0`)
9. **Harbor** (`harbor-framework/harbor`)

### Core Architectural Decision
**AGI 1.7 selects a zero-bloat Python Standard Library architecture** (`sqlite3` in WAL mode + `asyncio`/`concurrent.futures` + Win32 `ctypes` (`GlobalMemoryStatusEx`, `GetSystemTimes`, Job Objects) + `agy.exe` subprocess supervision + **isolated `Harbor` environment strictly for official Terminal-Bench 2.0 container grading**) rather than installing multiple heavy competing frameworks into the primary runtime environment.

## 3. Detailed Justification: Why Competing Heavy Frameworks Are Not Installed into the Primary Environment

### 3.1 Python 3.14 & Windows Dependency Hygiene
The host environment executes **CPython 3.14** on Windows x86_64 (`<USER_HOME>\AppData\Roaming\uv\python\cpython-3.14-windows-x86_64-none\python.exe` and `.venv`). Installing monolithic frameworks such as `ai-os`, `crewai`, `letta`, or `openhands-ai` pulls in over 150 transitive dependencies (`chromadb`, `onnxruntime`, `grpcio`, `litellm`, `ray`, `torch`), many of which lack prebuilt C-extension wheels for Python 3.14 on Windows or introduce conflicting `pydantic` / `protobuf` / `typing-extensions` versions. By building the AGI 1.7 runtime core exclusively on the **Python 3.14 Standard Library** (`sqlite3`, `asyncio`, `concurrent.futures`, `subprocess`, `ctypes`, `hashlib`, `json`, `ast`, `urllib.parse`, `ipaddress`), AGI 1.7 achieves zero installation fragility and sub-second startup times.

### 3.2 Directive 0 Sole-Model Policy (`gemini-3.8-flash-high` via `agy.exe`)
External frameworks (LangGraph, PydanticAI, CrewAI, AutoGen, Letta, Mem0) assume direct REST API keys (`OPENAI_API_KEY`, `GEMINI_API_KEY`) and make hidden internal LLM calls (e.g., Mem0 calling `gpt-4o-mini` for memory extraction, or AutoGen broadcasting full chat histories to every participant). Under **Directive 0**, AGI 1.7 must route 100% of LLM reasoning exclusively through `%LOCALAPPDATA%\agy\bin\agy.exe --model gemini-3.8-flash-high` with zero silent model fallbacks. Furthermore, our Phase 0 audit (`docs/AGI_1_7_BASELINE_AUDIT.md`, **Defect 7**) proved that `agy.exe` requires strict **working-directory isolation** (`D:\AGI_Evaluation\AGI_1_7_OMEGA_COMMAND\isolated_cwd`) and cumulative-session token normalization—behaviors that no off-the-shelf third-party SDK implements.

### 3.3 Host Memory Headroom Preservation
During active benchmark campaigns and OSWorld VM downloads (`PID 20556` and `PID 22884`), available physical RAM on the Windows host fluctuates between **1.8 GB and 2.9 GB**. Running external orchestration servers (Temporal Server, Letta Postgres/Chroma server, or multiple OpenHands Docker runtime containers) would consume **1.0 GB to 2.5 GB of resident RAM**, starving `agy.exe` workers and triggering Windows commit-limit exhaustion (`0xC000012D`). AGI 1.7's native `sqlite3` WAL engine + `ctypes` `ResourceGovernor` consumes **< 25 MB of resident memory**, preserving maximum RAM headroom for active `agy.exe` and benchmark tasks.
